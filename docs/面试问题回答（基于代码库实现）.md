- 节点把更新后的上下文通过 `Map.of(WORKFLOW_CONTEXT_KEY, context)` 回写：  
  - 示例：[CodeGeneratorNode.java](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/langgraph4j/node/CodeGeneratorNode.java#L44-L48)  
  - 示例：[ImageCollectorNode.java](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/langgraph4j/node/ImageCollectorNode.java#L91-L95)

补充：`WorkflowContext` 虽实现 `Serializable`，但代码库中未看到 checkpointer / Redis / DB 等外部存储接入，因此不具备“断点续跑/恢复”的能力。

### 2) 长任务（例如 2 分钟）+ 刷新/宕机：生成任务会怎样？能恢复吗？

结论：当前仓库实现偏“在线执行 + 流式输出”，**不支持任务级恢复**；刷新/断线与宕机的表现取决于链路。

**A. LangGraph4j 工作流链路（`CodeGenWorkflow`）**

- 执行方式是单次 `workflow.stream(...)` 跑到底，状态仅在进程内存中流转：  
  - [CodeGenWorkflow.executeWorkflow](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/langgraph4j/CodeGenWorkflow.java#L73-L101)
- 客户端刷新/断线：后端没有“恢复点”，最多是前端收不到后续事件。
- 服务进程宕机：内存态丢失，无法从中间节点继续，只能重启后重新触发。

**B. 对外 SSE 链路（线上实际接口）**

- 对外 SSE 端点为 `GET /api/app/chat/gen/code`：

### 2) SSE 长连接 + Nginx：缓冲/超时问题怎么配？

仓库内未包含 nginx 配置文件（只包含 Vite dev proxy），因此这里属于“部署通用实践”口述点：

- Nginx：通常需要关闭 buffering（避免积攒导致前端不实时），并拉长 read_timeout/send_timeout。
- Spring Boot：确保是 streaming 输出；MVC 的 SseEmitter 场景还需调 async timeout（当前对外接口是 WebFlux Flux）。

## 补充：面试拷打与系统风险深挖

本节针对项目中可能被“面试拷打”的薄弱点、设计权衡及潜在风险进行整理。

### 1) 代码解析策略：正则 vs AST，全量 vs 流式？

**拷打点**：HTML/CSS/JS 解析是用什么技术实现的？如果 LLM 输出格式稍微变一下（比如不带语言标识）怎么办？是大字符串一次性解析还是流式解析？

- **当前实现**：**正则全量解析**。
  - 使用 `Pattern.compile("```html\\s*\\R([\\s\\S]*?)\\s*```", ...)` 进行匹配：
    - [HtmlCodeParser.java](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/core/parser/HtmlCodeParser.java#L25)
    - [MultiFileCodeParser.java](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/core/parser/MultiFileCodeParser.java#L34)
  - **全量而非流式**：代码必须等 LLM 输出完毕，拼成一个大 `String` 后才进行正则匹配。
- **风险与缺陷**：
  - **内存消耗**：如果生成代码非常长（例如几 MB），大字符串驻留内存可能导致 OOM。
  - **正则回溯**：复杂的 `[\s\S]*?` 在极端输入下可能导致正则回溯性能问题（ReDoS）。
  - **容错性**：虽然有兜底（未匹配到则返回原文），但如果 LLM 输出了 markdown 但没有 `html` 标签，解析可能会失效或返回空。
- **面试应对**：承认当前是 MVP 实现，优化方案是引入流式状态机解析（边接收边提取），或者换用基于 AST 的解析库（但这通常需要先保存为文件）。

### 2) 资源泄漏与稳定性：临时文件清理与 Zip 炸弹

**拷打点**：下载时生成的 Zip 文件怎么清理？如果大量用户下载，磁盘会不会爆？

- **当前实现**：**有缓存但无自动清理**。
  - Zip 生成在 `DOWNLOAD_TEMP_DIR`，如果文件存在且较新则复用：
    - [ProjectDownloadServiceImpl.buildZipFile](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/service/impl/ProjectDownloadServiceImpl.java#L178-L194)
  - **缺失**：代码中没有定时任务或 LRU 策略来清理过期的 Zip 文件。长时间运行 `tmp/downloads` 目录会无限膨胀。
- **面试应对**：这是一个设计疏忽。生产环境应配合 `@Scheduled` 定时任务清理 `lastModified` 超过一定时间的文件，或者在生成时使用临时文件并在响应后立即删除（但这会牺牲复用性）。

### 3) 数据库事务与数据一致性

**拷打点**：`chatToGenCode` 涉及数据库写入和 LLM 调用，为什么没加 `@Transactional`？如果 LLM 生成失败，用户的提问记录还在吗？

- **当前实现**：**有意不加事务**。
  - 流程：保存 User 消息 -> 调用 LLM（耗时） -> 保存 AI 响应。
    - [AppServiceImpl.chatToGenCode](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/service/impl/AppServiceImpl.java#L480-L515)
- **设计理由**：
  - LLM 生成是**长耗时操作**（可能几十秒），如果在事务中等待，会长时间占用数据库连接，导致连接池耗尽（Connection Starvation）。
  - **一致性妥协**：允许“用户提问保存成功，但 AI 生成失败”的情况。这在业务上是可以接受的（用户可以看到自己的提问，然后重试）。
- **优化点**：如果必须保证一致性，可以使用**最终一致性**方案（消息队列异步处理），或者在失败时手动回滚（删除那条 user message）。

### 4) Token 成本控制与恶意刷量

**拷打点**：如何防止用户恶意输入超长文本消耗 Token？你的系统有 Token 预算控制吗？

- **当前实现**：**仅有 QPS 限流，无 Token 级风控**。
  - 只有基于 Redisson 的次数限流（每用户每秒 n 次）：
    - [AppController.chatGenerateCode](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/controller/AppController.java#L194)
  - **缺失**：代码中未对 `userMessage` 长度做校验，也未计算 LLM 返回的 Token 数并扣费。
- **风险**：用户可以发送极长的 prompt 导致 API 成本激增。
- **面试应对**：生产环境需要在 Controller 层增加文本长度校验（如 `userMessage.length() < 2000`），并在接入层（Facade）对接 Token 计费系统（预扣除+实结）。

### 5) 安全细节：密码加盐与环境变量

**拷打点**：密码加密的盐值 `SALT` 是怎么管理的？

- **当前实现**：依赖系统环境变量 `System.getenv("SALT")`。
  - [UserServiceImpl.encryptPassword](file:///c:/Users/xyz/Desktop/javalearn/ai-zero-code-hub/src/main/java/com/swu/aiZeroCodeHub/service/impl/UserServiceImpl.java#L103-L107)
- **风险**：
  - 代码中未做判空处理。如果环境变量未配置，`SALT` 为 null，凭借 `(SALT+password)` 拼接逻辑，实际变成了 `("null"+password)`，这会导致所有用户的盐值变成字符串 "null"，极易被彩虹表破解。
- **优化**：必须在启动时（Configuration 阶段）校验环境变量是否存在，不存在则拒绝启动；或者使用更安全的 BCrypt（Spring Security 默认）替代 MD5。
